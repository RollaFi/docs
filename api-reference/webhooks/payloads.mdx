## Payload structure

Every webhook has the same envelope. Transaction details live under `data`.

```json
{
  "event": "transaction.completed",
  "event_id": "8f2a1c44-9b3e-5d61-a2f7-1e9c0b4d6a55",
  "created_at": "2026-06-10T12:00:05.000Z",
  "data": {
    "transaction_id": "…",
    "reference": "…",
    "type": "deposit | payout",
    "status": "pending | completed | failed",
    "rail": "fiat | stablecoin",
    "currency": "…",
    "amount": 0,
    "source_amount": 0,
    "source_currency": "…",
    "destination_amount": 0,
    "destination_currency": "…",
    "fee_amount": 0,
    "description": "…",
    "timestamp": "…",
    "sender": { },
    "beneficiary": { },
    "network": { },
    "metadata": { }
  }
}
```

### Field reference

| Field | Description |
|-------|-------------|
| `event` | Event type — see [Events](/api-reference/webhooks/events) |
| `event_id` | Stable id for the logical event (use to deduplicate) |
| `created_at` | When the event was generated (ISO 8601) |
| `data.transaction_id` | Rolla transaction id |
| `data.reference` | Transaction reference (the external reference) |
| `data.type` | `deposit` or `payout` |
| `data.status` | `pending`, `completed`, or `failed` |
| `data.rail` | `fiat` or `stablecoin` |
| `data.amount` / `data.currency` | The **net** amount the counterparty receives, and its currency — a deposit's credited amount, or a payout's amount to the beneficiary. Equals `destination_amount`. |
| `data.source_amount` / `data.source_currency` | The debit leg. For a **payout** this is the **gross** amount, i.e. `amount` **+ fee**; for FX it's the source-currency amount. |
| `data.destination_amount` / `data.destination_currency` | The credit leg — what the beneficiary/wallet actually receives. |
| `data.fee_amount` | Fee applied, in smallest units |
| `data.sender` | Sender details — present for **deposits**, otherwise `null` |
| `data.beneficiary` | Beneficiary details — present for **payouts**, otherwise `null` (see below) |
| `data.network` | On-chain details — present for **stablecoin** transactions, otherwise `null` |
| `data.metadata` | Any metadata you supplied when creating the transaction |

<Info>
  **Amounts** are in each currency's **smallest unit** — NGN kobo, USD cents (**100 = \$1.00**), and the base unit for stablecoins — consistent with the rest of the Rolla API.
</Info>

<Tip>
  For a payout, **`amount`** is what you asked to send (the beneficiary's amount). **`source_amount`** is what's debited from your wallet, including the fee. So `source_amount = amount + fee_amount` (when fees are charged on top).
</Tip>

### The `beneficiary` object (payouts)

Always contains this whitelisted set; fields are `null` when not applicable. Internal fields (your `business_id`, row timestamps) are never included.

`id` · `account_name` · `account_number` · `bank_name` · `bank_code` · `bank_address` · `currency` · `withdrawal_method` · `routing_number` · `swift_code` · `iban` · `bic` · `sort_code` · `intermediary_bank_name` · `intermediary_bank_routing_number` · `wallet_address` · `wallet_chain` · `email` · `contact_person` · `label` · `beneficiary_address`

<Note>
  For a one-time (inline) beneficiary, `id` is the literal string `"inline-temp"`. For a saved beneficiary it's the beneficiary's UUID. The samples below trim `null` fields for readability — the live payload includes all of the above.
</Note>
