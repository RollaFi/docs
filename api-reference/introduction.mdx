The Rolla Developer API is a REST API: JSON in, JSON out, predictable resource-based paths. This page covers the conventions every endpoint shares.

**Base URL**: `https://api.rolla.xyz/api/v1/external`

## Authentication

Every request must carry your API key in the `X-API-Key` header:

```bash
curl "https://api.rolla.xyz/api/v1/external/banks" \
  -H "X-API-Key: your_api_key_here"
```

Keys are created in the [Rolla Dashboard](https://app.rolla.xyz) under **Settings → API Keys**, and can optionally be locked to allowlisted IP addresses. Note that [Withdraw Funds](/api-reference/endpoint/wallet/withdraw) and [Rolla Transfer](/api-reference/endpoint/wallet/transfer) **require** the key to have at least one allowlisted IP.

See [Authentication](/concepts/authentication) for key management, environments, and security guidance.

<Warning>
  Keep your API key secure. Do not expose it in client-side code or public repositories.
</Warning>

## Acting on a tenant account (`X-Account-Id`)

If your business is a Rolla **white-label tenant**, a single API key can act on any account inside your tenancy — your own account, or any account you've onboarded under it. Add the optional **`X-Account-Id`** header naming the target account, and the **entire** request is scoped to that account: onboarding, documents, wallets, funding instructions, payouts, beneficiaries — everything runs as that account.

```bash
# Fetch funding instructions for one of your tenant's accounts
curl -X GET "https://api.rolla.xyz/api/v1/external/accounts/{accountId}/funding-instructions" \
  -H "X-API-Key: your_tenant_api_key" \
  -H "X-Account-Id: 3f1c2d4e-5a6b-7c8d-9e0f-1a2b3c4d5e6f"
```

| Behaviour | Result |
|-----------|--------|
| Header omitted | The request acts as your own (the API key's) account — standard behaviour. |
| Header set to an account in your tenancy | The request is scoped to that account. |
| Header set, but your key isn't a tenant key | `403` — `X-Account-Id` is only available to tenant API keys. |
| Header naming an account outside your tenancy | `404` — Account not found in your tenancy. |

<Info>
  Accounts you create with a tenant API key (via `POST /accounts`) are automatically added to your tenancy, so you can immediately address them with `X-Account-Id` afterwards. Accounts that onboard themselves through your white-label app are part of your tenancy too.
</Info>

## Response format

Successful responses carry `success: true` with the payload under `data`; errors carry the HTTP code and a message:

<CodeGroup>

```json Success
{
  "status": 200,
  "message": "Banks retrieved successfully",
  "success": true,
  "data": { ... }
}
```

```json Error
{
  "status": 401,
  "message": "Invalid or inactive API key"
}
```

</CodeGroup>

`status` is the HTTP status code as a number in both cases. Some errors add a machine-readable `code` — the full taxonomy is in [Errors](/concepts/errors).

## Amounts

Unless a route documents otherwise, numeric `amount` fields use each currency's **smallest unit** in requests and responses — NGN **kobo**, USD **cents** (`100` = $1.00), etc. Fractional amounts are rejected. See [Amounts & Currencies](/concepts/amounts-and-currencies).

## Pagination

List endpoints that paginate take `page` and `pageSize` (max `100`) and return `totalCount`, `totalPages`, and `hasMore` alongside the rows. See [Pagination](/concepts/pagination).

## Idempotency

There is no global idempotency header; money-moving requests should follow the lookup-before-retry pattern with your own `externalReference`. See [Idempotency & Retries](/concepts/idempotency).

## Webhooks

Instead of polling for status changes, register a webhook endpoint and receive [signed events](/api-reference/webhooks/overview) for every deposit, payout, fee, and account update.
