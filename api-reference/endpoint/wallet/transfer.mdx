---
title: 'Rolla Transfer'
openapi: 'POST /wallet/transfer'
---

Send funds to another Rolla business instantly and fee-free. You can identify the recipient by their registered email address, Rolla tag, or a saved `beneficiaryId` with `withdrawal_method: rolla_transfer`.

The request `amount` is always in the **smallest currency unit** for `currency` (USD = cents — **100** = **\$1.00** USD; NGN = kobo).

<Info>
  **Transferring from a specific merchant (tenant keys):** if your API key is a white-label tenant key managing multiple merchants, add the [`X-Account-Id`](/api-reference/introduction#acting-on-a-tenant-account-x-account-id) header set to the account ID you want to send **from** — the transfer is then debited from **that account's wallet**. Without it, it runs against your own (parent) account. This is how you move funds between your institutional account and merchant wallets.
</Info>

## Example Request (by email)

```bash
curl -X POST "https://api.rolla.xyz/api/v1/external/wallet/transfer" \
  -H "X-API-Key: your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 100,
    "currency": "USD",
    "destinationCurrency": "USD",
    "recipient": "partner@example.com",
    "description": "Invoice payment",
    "saveBeneficiary": true,
    "metadata": { "invoice_id": "INV-2026-042" }
  }'
```

## Example Request (by saved beneficiary)

```bash
curl -X POST "https://api.rolla.xyz/api/v1/external/wallet/transfer" \
  -H "X-API-Key: your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 100,
    "currency": "USD",
    "destinationCurrency": "USD",
    "beneficiaryId": "d4e5f6a7-b8c9-0123-defa-456789012345",
    "description": "Invoice payment"
  }'
```

## Example Request (cross-currency)

Cross-currency transfers require a `rateToken` from the [`GET /wallet/rates`](/api-reference/endpoint/wallet/rates) endpoint first.

```bash
curl -X POST "https://api.rolla.xyz/api/v1/external/wallet/transfer" \
  -H "X-API-Key: your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 100,
    "currency": "USD",
    "destinationCurrency": "NGN",
    "recipient": "partner@example.com",
    "rateToken": "rate_token_from_rates_endpoint",
    "description": "Cross-currency payment"
  }'
```

## Example Response

The `amount` you send uses the smallest unit of `currency` (USD = cents below). Ledger fields such as `source_amount` mirror that unit.

```json

  "message": "Transfer initiated successfully",
  "success": true,
  "data": {
    "transfer_reference": "TRANSFER-1712345678-abc12345",
    "sender_transaction": {
      "id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
      "transaction_type": "withdrawal",
      "status": "completed",
      "description": "Invoice payment",
      "external_reference": "TRANSFER-1712345678-abc12345-DEBIT",
      "fee_amount": 0,
      "source_amount": 100,
      "destination_amount": 100,
      "source_currency": "USD",
      "destination_currency": "USD",
      "metadata": { "invoice_id": "INV-2026-042" },
      "created_at": "2026-03-23T13:45:28.138Z",
      "updated_at": "2026-03-23T13:45:28.263Z"
    },
    "recipient_transaction": {
      "id": "b2c3d4e5-f6a7-8901-bcde-f12345678901",
      "transaction_type": "deposit",
      "status": "completed",
      "description": "Transfer from Acme Holdings",
      "external_reference": "TRANSFER-1712345678-abc12345-CREDIT",
      "fee_amount": 0,
      "source_amount": 100,
      "destination_amount": 100,
      "source_currency": "USD",
      "destination_currency": "USD",
      "payer": { "name": "Acme Holdings", "bank_name": "Rolla" },
      "created_at": "2026-03-23T13:45:28.201Z",
      "updated_at": "2026-03-23T13:45:28.201Z"

    "pending_claim": null
  }

```

Both legs share one `transfer_reference`; each transaction's own `external_reference` is that
reference suffixed with `-DEBIT` on the sender side and `-CREDIT` on the recipient side. On a
cross-currency transfer the sender leg's `transaction_type` is `fx_withdrawal` rather than
`withdrawal`, and its `destination_amount` / `destination_currency` are the converted amount in
the recipient's currency.

## Key Behaviours

<Info>
  **Free transfers** — Rolla-to-Rolla transfers have zero fees.
</Info>

<Info>
  **Payer on the receiving side** — `recipient_transaction`, and every webhook for it, carries `payer` with the sending account's `name` and `bank_name: "Rolla"`, so the recipient can see who the funds came from. The sender's email is never included.
</Info>

<Info>
  **`pending_claim`** — If the recipient email matches multiple Rolla businesses, funds are held in escrow and a `pending_claim` object is returned. The recipient must log in and claim the funds.
</Info>

<Warning>
  **IP whitelisting** — This endpoint requires your API key to have IP whitelisting configured, or the request must originate from a whitelisted IP.
</Warning>

## Parameters

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `amount` | number | Yes | Amount in the smallest currency unit for `currency` (e.g. cents for USD: **100** = \$1.00 USD; kobo for NGN) |
| `currency` | string | Yes | Source currency code (e.g. `USD`) |
| `destinationCurrency` | string | Yes | Recipient's currency code |
| `recipient` | string | Conditional | Recipient's email or Rolla tag. Required if `beneficiaryId` not provided |
| `beneficiaryId` | string (UUID) | Conditional | Saved beneficiary ID with `withdrawal_method: rolla_transfer`. Required if `recipient` not provided |
| `description` | string | No | Transfer description (max 500 chars) |
| `saveBeneficiary` | boolean | No | Auto-save the recipient as a beneficiary for future transfers |
| `rateToken` | string | Conditional | Required for cross-currency transfers — obtain from `GET /wallet/rates` |
| `metadata` | object | No | Your own key/value data, returned on the transaction and its webhooks. See [Attaching your own metadata](#attaching-your-own-metadata) |

## Attaching your own metadata

Pass a `metadata` object to carry your own identifiers on the transfer — an order id, an invoice number, or, when you forward funds received from a customer, who originally paid. Rolla stores it verbatim, never interprets it, and returns it unchanged on the transaction and every webhook for it.

```bash
curl -X POST "https://api.rolla.xyz/api/v1/external/wallet/transfer" \
  -H "X-API-Key: your_api_key_here" \
  -H "X-Account-Id: 8f14e45f-ceea-467a-9575-2d0c3b1f7c21" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 5000,
    "currency": "USD",
    "destinationCurrency": "USD",
    "recipient": "@acmeholdings",
    "metadata": {
      "original_payer": "Contoso Retail UK Ltd",
      "order_id": "ORD-88213"
    }
  }'
```

**Which side carries it.** `metadata` is always returned on the **sending** side (`sender_transaction`). It is also returned on the **receiving** side (`recipient_transaction`) when both accounts belong to the **same owner** — for example a merchant account forwarding funds to your institutional account. A transfer to another company's account never shows them your metadata.

**Limits** are the same as for [payouts](/api-reference/endpoint/wallet/withdraw#attaching-your-own-metadata): at most **20** keys, keys up to **64** characters, values that are a `string` (up to **500** characters), `number`, `boolean` or `null` — no nested objects or arrays. Exceeding any of them returns `400` and the transfer is not made.

<Warning>
  Metadata is returned to anyone who can read the transaction and is sent to your webhook endpoints. Don't put secrets or personal data in it that you wouldn't want echoed back.
</Warning>
