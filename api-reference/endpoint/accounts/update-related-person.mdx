---
title: 'Update Related Person'
openapi: 'PUT /accounts/{accountId}/related-persons/{personId}'
---

Updates a related person on a business account's application. Provided fields are merged into the existing record.

<Info>
  `taxId` can be patched onto an existing person — useful for representatives added before
  the field existed, whose USD issuance is blocked until one is supplied. See
  [Add Related Person](/api-reference/endpoint/accounts/add-related-person#government-identifier)
  for the per-country formats.
</Info>

## Mandatory and optional fields

Every field is optional in this request — provided fields are merged, omitted fields keep
their stored values. The same fields are mandatory **before submission** as on
[Add Related Person](/api-reference/endpoint/accounts/add-related-person#mandatory-and-optional-fields):
`firstName`, `lastName`, `email`, `phone`, `dateOfBirth`, `sourceOfWealthExplanation`, a
government identifier, and all five `currentAddress` fields.

`ownershipPercentage` and `roles` stay optional throughout.

<Warning>
  `currentAddress` is all-or-nothing. Send it and all five fields must be present —
  there is no patching a single line of an address.
</Warning>

## Example Request

```bash
curl -X PUT "https://api.rolla.xyz/api/v1/external/accounts/eec3cbed-79d8-4370-87a0-b6be9e287337/related-persons/a3d4f21e-f499-488f-8508-43228dfea485" \
  -H "X-API-Key: your_api_key_here" \
  -H "Content-Type: application/json" \
  -d '{
    "ownershipPercentage": 75
  }'
```

## Example Response

```json
{
  "status": 200,
  "message": "Related person updated successfully",
  "success": true,
  "data": {
    "id": "a3d4f21e-f499-488f-8508-43228dfea485",
    "firstName": "Jane",
    "lastName": "Doe",
    "roles": ["Beneficial Owner", "Director"],
    "email": "jane@betalogistics.com",
    "phone": "+13025550124",
    "dateOfBirth": "1985-09-21",
    "ownershipPercentage": 75,
    "currentAddress": {
      "street": "5 Oak St",
      "city": "Wilmington",
      "state": "DE",
      "postalCode": "19801",
      "country": "US"
    },
    "taxId": "123456789"

```

`data` is the whole merged record, not just the fields you sent.

## Errors

| Status | When |
|--------|------|
| `400` | Validation failed |
| `404` | Account not found, or no related person with that `personId` is on its application (`Related person not found`) |
